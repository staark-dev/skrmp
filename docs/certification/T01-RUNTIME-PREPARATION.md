## 1. Log Origin Reconciliation

The `skrx_vehicles.log` with five failed hook installations was generated by a
**different binary** than the pre-M2.1 portable test DLL.

| Environment | DLL | Size | SHA-256 | Has VEHICLES? |
|------------|-----|------|---------|---------------|
| `SKR-Portable-Test/` | Pre-M2.1 | 263,680 | `d0153655...` | NO |
| Steam GTA (via injection) | M2.1-B | 890,880 | `f44528c9...` | YES (old prolog) |
| Deployment backup | M2.1-B | 890,880 | `f44528c9...` | YES (matches) |

**The log came from the Steam GTA SA installation:**
`C:\Program Files (x86)\Steam\steamapps\common\Grand Theft Auto San Andreas\SKR\skrx_vehicles.log`

The launcher was run from an external directory, resolved `SKR.Client.dll` via
`findDll()` (launcher dir → GTA dir fallback), injected the M2.1-B binary into
`gta_sa.exe`, and the DLL wrote its logs to `<gta_dir>\SKR\`.

**Evidence:** The `exit_trace.log` shows `SKR.Client.dll` loaded at base `0x6F060000`
with offsets up to `+0xA99CC` (~693 KB code section), consistent with the 890 KB
M2.1-B binary, not the 264 KB portable test binary.

The M2.1-B binary had VEHICLES hook code (logged `HOOK install` and
`ModelRegistry received`) but used the **wrong prolog signature** (`55 8B EC 83 EC 08`),
causing all five hook installations to fail with "prolog mismatch".

## 7. Operator Launch Procedure

### Prerequisites
- Steam GTA SA installed at default path
- `server-runtime-branded-test` running with SKRGate + `skrx_vehicles_test.pwn`
- Server config: server address + port known

### Steps

1. **Launch** via `SKRLauncher.exe` (from `SKR-Portable-Test/` or wherever normally run).
   The launcher will find `SKR.Client.dll` (908,288 bytes) and inject it.

2. **Connect** to the test server.

3. **Verify hook installation** in `<Steam GTA>\SKR\skrx_vehicles.log`:
   ```
   [tick] === SKRX VEHICLES Init ===
   [tick] HOOK PE check: TimeDateStamp=0x6372C39E SizeOfImage=0x27E000
   [tick] HOOK install: samp=0x<base> target=0x<base+1F080> (RVA 0x1F080)
   [tick] HOOK trampoline at 0x<addr>: 56 8B 74 24 08 E9 -> 0x<base+1F085>
   [tick] HOOK detour written at 0x<base+1F080> -> HookedCreate (0x<addr>)
   [tick] HOOK installed: trampoline=0x<addr> prolog=568B742408
   ```

   **Failure indicators:**
   - `HOOK PE check FAILED` → wrong samp.dll version loaded
   - `HOOK prolog mismatch` → should NOT appear with M2.1-C binary
   - No `HOOK PE check` line at all → old binary was loaded (check SHA-256)

4. **Verify ModelRegistry** (after connecting):
   ```
   [tick] ModelRegistry received: N models
   [tick] ModelRegistry: model 612 — OP215 registered=<bool> loaded=<bool>
   ```

5. **Test stock vehicle** — `/v 560` (Sultan):
   ```
   [tick] HOOK pass pool=<N> model=560 (no swap needed)
   ```

6. **Test custom vehicle** — `/v 612` (Volvo XC60):
   - If OP215 model loaded:
     ```
     [tick] HOOK swap pool=<N> proxy=400 -> model=612 swaps=1
     ```
     Vehicle renders as XC60.
   - If OP215 model not yet loaded:
     ```
     [tick] HOOK defer pool=<N> proxy=400 target=612 (model not loaded) defers=1
     ```
     Vehicle renders as Landstalker (proxy 400). Respawn after model loads.

7. **Verify diagnostics** — `/vm <vehicle_id>`:
   Shows true model, stock model, custom status.

8. **Destroy** — `/dv` — verify cleanup.

9. **Collect evidence:**
   - `SKR/skrx_vehicles.log` — full hook lifecycle
   - `SKR/op215.log` — OP215 model registration and loading
   - `SKR/skrx.log` — gateway handshake
   - Screenshot of vehicle in-game (if visual confirmation needed)
